# PaperCue 변경 기록 (한국어)

각 항목은 하나의 의미 있는 개발 단계를 기록합니다. 비밀값, 참여자 데이터, 대화 원문, 로컬 절대 경로는 기록하지 않습니다.

---

## 1. Git 및 비밀값 관리 강화

- **변경 날짜:** 2026-09-16
- **변경 목적:** 코드를 올리기 전에 데이터베이스·환경 파일·참여자 데이터가 실수로 Git에 들어가지 않도록 막기 위함.
- **주요 변경사항**
  - 저장소 루트와 `papercue-backend/`에 `.gitignore` 추가(`.env`, `data/`, `exports/`, `*.db`, `*.log`, `node_modules/`, `dist/` 등).
  - `app/models/`가 무시되지 않도록 `models/` 대신 루트 고정 패턴 `/models/` 사용.
  - 스테이징된 변경을 검사하는 `scripts/security_check.py` 추가(gitleaks가 있으면 함께 실행, 없으면 로컬 패턴 검사).
  - 안전한 기본값만 담은 `.env.example` 추가.
- **수정된 주요 파일:** `.gitignore`, `papercue-backend/.gitignore`, `papercue-backend/.env.example`, `papercue-backend/scripts/security_check.py`
- **데이터베이스 변경 여부:** 없음
- **테스트 결과:** 검사기가 토큰·개인 키·비밀번호·절대 경로·이메일·금지 파일을 탐지하는지 수동으로 확인함.
- **보안 관련 확인사항:** gitleaks 미설치 → 로컬 패턴 검사로 대체. 스테이징 검사 통과.
- **남아 있는 문제:** gitleaks를 설치하면 더 넓은 규칙으로 검사할 수 있음.

## 2. 로컬 백엔드 핵심 구현

- **변경 날짜:** 2026-09-16
- **변경 목적:** 논문 → 논문 단위 → 청중 모델 → 검색 → 개입 판단 → 단서 생성 → 안전성 검사로 이어지는 로컬 파이프라인 구현.
- **주요 변경사항**
  - FastAPI 서버(기본 `127.0.0.1`), SQLite 스키마, 세션 삭제 시 연쇄 삭제.
  - Ollama 제공자와 명시적 Mock(시뮬레이션) 제공자. 세션마다 제공자와 단서 언어(한국어/영어) 선택.
  - 근거 추출기, 결정론적 청중 모델 갱신 규칙, 개입 판단 엔진, 단서 생성기, 안전성·근거성 필터.
  - 단계별 처리 기록(`pipeline_traces`)과 로컬 처리 오류 기록(`processing_errors`).
  - 영어·한국어 예시 데이터, 데모 스크립트, 보관 기간 정리 스크립트, ASR/TTS/모바일 연결용 인터페이스.
- **수정된 주요 파일:** `app/` 전체, `sample_data/`, `scripts/demo.py`, `pyproject.toml`
- **데이터베이스 변경 여부:** 있음(스키마 v2 신규 생성)
- **테스트 결과:** Mock 모드 데모(영어·한국어)에서 각각 “privacy first—local processing”, “개인정보 먼저—로컬 처리” 생성 확인.
- **보안 관련 확인사항:** 외부 네트워크 호출은 로컬 주소로 제한된 Ollama 호출뿐임을 확인. 로그에 발화 원문 없음.
- **남아 있는 문제:** Mock 규칙은 단순한 키워드 규칙이며 실제 언어 모델을 대신하지 못함.

## 3. 백엔드 테스트

- **변경 날짜:** 2026-09-16
- **변경 목적:** 동의, 삭제, 개인정보, 갱신 규칙, 필터, Ollama 오류 처리를 자동으로 검증.
- **주요 변경사항:** 테스트 73개 추가(`tests/`).
- **수정된 주요 파일:** `tests/*.py`
- **데이터베이스 변경 여부:** 없음(테스트마다 임시 DB 사용)
- **테스트 결과:** 73개 통과.
- **보안 관련 확인사항:** 처리 기록에 발화 원문이 복제되지 않는지 확인하는 테스트에서 실제 문제를 발견하고 수정함(결정 기록에는 ID만 저장).
- **남아 있는 문제:** 실제 Ollama 모델을 사용한 품질 평가는 아직 없음(HTTP 계층은 가짜 로컬 서버로 검증).

## 4. 연구자 대시보드 기반

- **변경 날짜:** 2026-09-17
- **변경 목적:** 백엔드를 작성하지 않은 연구자도 처리 과정을 한국어로 확인할 수 있게 하기 위함.
- **주요 변경사항**
  - Vite + 순수 JavaScript 대시보드(런타임 의존성 없음, 개발 의존성은 vite·vitest·jsdom만).
  - 한국어 문구를 `src/i18n/ko.js`에 분리. 모든 데이터는 `textContent`로만 표시(HTML 주입 방지).
  - 시스템 개요, 논문 지식 구조, 세션 작업 공간 페이지.
  - 영구 삭제 시 체크박스와 ‘삭제’ 입력을 모두 요구하는 확인 창.
- **수정된 주요 파일:** `dashboard/`의 설정 파일, `src/api.js`, `src/dom.js`, `src/components.js`, `src/i18n/ko.js`, `src/styles.css`, `src/pages/overview.js`, `src/pages/papers.js`, `src/pages/session.js`
- **데이터베이스 변경 여부:** 없음
- **테스트 결과:** 이후 대시보드 테스트 단계에서 함께 검증.
- **보안 관련 확인사항:** 외부 글꼴·CDN·추적기 없음. API는 같은 출처의 상대 경로만 사용. 브라우저 저장소에 참여자 데이터를 저장하지 않음.
- **남아 있는 문제:** 브라우저 자동화 도구로 화면을 직접 확인하지는 못함(jsdom에서 실제 서버와 연결해 모든 페이지 렌더링을 확인함).

## 5. 청중 모델 변경 이력 시각화

- **변경 날짜:** 2026-09-17
- **변경 목적:** 청중 모델의 각 믿음이 어떤 근거로 생기고 바뀌었는지 한눈에 확인하기 위함.
- **주요 변경사항**
  - ‘진화하는 청중 모델’ 페이지: 10개 차원(불확실성 포함) 카드, 믿음별 현재 값·신뢰도·출처·근거·갱신 이유.
  - 색과 한국어 배지를 함께 사용: 프로필 가설(회색 점선), 대화 근거(파랑), 명시적 확인(초록), 상충 근거(주황), 만료된 가설(취소선).
  - 대체된 믿음에 ‘이전 상태 → 현재 상태’ 표시, 발화 순서별 신뢰도 그래프와 정확한 수치 표.
  - 구조화된 기록을 한국어 문장으로 바꾸는 `src/explain.js`(숨겨진 모델 추론은 사용하지 않음).
  - 백엔드: 변경 이력 조회에 근거 유형(`evidence_type`)을 함께 반환.
- **수정된 주요 파일:** `dashboard/src/pages/audience.js`, `dashboard/src/explain.js`, `app/repositories/audience.py`
- **데이터베이스 변경 여부:** 없음(조회 쿼리만 변경)
- **테스트 결과:** 백엔드 73개 통과.
- **보안 관련 확인사항:** 청중 모델 설명 문장이 사람의 성향을 단정하지 않도록 고정된 문장 틀만 사용.
- **남아 있는 문제:** 추출기가 남긴 관찰 문장은 영문이며, 대시보드는 한국어 설명과 함께 원문을 보조로 표시함.

## 6. 턴별 처리 과정 기록

- **변경 날짜:** 2026-09-17
- **변경 목적:** 발화 하나가 12단계를 거쳐 어떻게 바뀌는지 연구자가 직접 확인하게 하기 위함.
- **주요 변경사항**
  - ‘턴별 처리 과정’ 페이지: 12단계를 펼침 목록으로 표시(상태, 처리 주체, 모델, 프롬프트 버전, 소요 시간, 검증 결과, 입력 요약, 구조화된 출력, 한국어 설명).
  - 1~6단계는 발화 입력 처리 기록, 7~12단계는 선택한 단서 요청 기록(없으면 발화 입력 시의 개입 평가)에서 가져옴.
  - `개발자용 JSON 보기`는 기본으로 숨김.
  - 백엔드: 결정 기록에 판단 이유 파라미터와 근거 ID를 저장(원문은 저장하지 않음), 믿음 변경 기록에 출처 유형 포함.
- **수정된 주요 파일:** `dashboard/src/pages/trace.js`, `app/services/pipeline.py`, `pyproject.toml`
- **데이터베이스 변경 여부:** 없음(기존 JSON 열에 필드 추가)
- **테스트 결과:** 백엔드 73개 통과.
- **보안 관련 확인사항:** 처리 기록에는 참조 ID, 상태, 점수, 짧은 이유만 저장. 숨겨진 추론은 저장·표시하지 않음.
- **남아 있는 문제:** 오류로 중단된 기록은 이후 단계가 ‘실행되지 않음’으로 표시됨.

## 7. 단서 생성 분석, 동작 안내, 앱 연결

- **변경 날짜:** 2026-09-17
- **변경 목적:** 단서가 전달되거나 보류된 이유를 설명하고, 시스템 구조를 한국어로 안내하기 위함.
- **주요 변경사항**
  - ‘단서 생성 분석’ 페이지: 요청 발화, 대화 단계, 미해결 질문, 사용된 믿음, 검색 단위와 유사도, 개입 점수 구성(가중치·기여), 선택 행동, 처음 후보와 최종 단서, 근거 ID, 단어 수, 반복·민감 추론·근거 없는 주장 검사, 최종 상태(8가지 한국어 상태).
  - 단서가 없을 때도 관찰 가능한 이유를 한국어로 표시(예: “현재 질문과 직접 연결되는 논문 근거를 찾지 못해 단서를 생성하지 않았습니다.”).
  - ‘시스템 동작 이해하기’ 페이지: 모듈별 설명, 처리 흐름도, 개념 구분, 개인정보 질문 워크스루, ‘하지 않은 추론’ 설명, Mock 예시 실행 버튼.
  - 해시 기반 라우터와 세션 선택기(선택한 세션 ID만 메모리와 URL에 보관).
- **수정된 주요 파일:** `dashboard/src/pages/cues.js`, `dashboard/src/pages/guide.js`, `dashboard/src/main.js`
- **데이터베이스 변경 여부:** 없음
- **테스트 결과:** 실제 로컬 서버(Mock 모드)에 연결해 6개 페이지가 오류 없이 렌더링되는 것을 확인.
- **보안 관련 확인사항:** 예시 데이터는 합성 데이터이며 `sample_data/`에서 빌드 시 가져옴. 외부 요청 없음.
- **남아 있는 문제:** 없음.

## 8. 대시보드 추적·개인정보 테스트

- **변경 날짜:** 2026-09-17
- **변경 목적:** 대시보드의 한국어 표시, 추적 단계, 개인정보 보호 동작을 자동으로 검증.
