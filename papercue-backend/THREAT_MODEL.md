# PaperCue threat model (local research prototype)

**Assets:** typed conversation turns, derived audience models, listener profiles, unpublished paper content, and exports.
**Trust boundary:** the researcher's own computer. Everything outside `127.0.0.1` is untrusted.

| # | Threat | Mitigations in this prototype | Residual risk / next steps |
|---|---|---|---|
| 1 | **Accidental network exposure** (binding to `0.0.0.0`, a permissive CORS policy, or a remote model host) | The default host is `127.0.0.1`; non-loopback hosts are refused unless `PAPERCUE_ALLOW_NON_LOCAL_BIND=true`. CORS allows loopback origins only, with no wildcard. `OLLAMA_BASE_URL` must be loopback. The status page and dashboard warn about each misconfiguration. Security headers are set (CSP, `X-Frame-Options`, `nosniff`, `no-referrer`). | There is no authentication: any local process or user on the machine can call the API. Do not run it on shared machines. |
| 2 | **Unauthorized local database access** | The SQLite file is created with `0600`, `secure_delete` is on, the database is git-ignored, and a deletion/retention workflow exists. | The file is not encrypted at rest; rely on full-disk encryption. Backups and Time Machine may copy it. |
| 3 | **Prompt injection in paper or conversation text** | Untrusted text is sent as JSON data, and every system prompt states that embedded instructions are data. Output must match a strict schema. The LLM cannot write beliefs or decide delivery. Evidence quotes must appear verbatim in the turn. Cue IDs must reference retrieved units, and the filter blocks URLs, code, multi-sentence answers, unsupported claims, and forbidden claims. | A model can still be steered into poor but schema-valid cues within these limits. |
| 4 | **Model hallucination** | Validation happens before storage. Values come from fixed vocabularies, confidence is assigned by code, and unit keywords must occur in their chunks. Numbers and claim words must appear in grounding units. Retrieval thresholds apply. When grounding is weak, the system falls back to a verification cue or returns no cue. Invalid JSON fails safely after a limited retry. | Short-explanation text from the labeller is not verified sentence-by-sentence; presenters can edit units. |
| 5 | **Inference of sensitive traits** | Fixed audience dimensions; sensitive and characterisation term lists (English and Korean) are applied to profiles, evidence, state, proposals, and cues. Knowledge judgments from single non-explicit signals are downgraded. Rejected profile fields are not echoed. | Term lists are incomplete; paraphrased sensitive inferences may pass. Human review of traces is still needed. |
| 6 | **Excessive data retention** | `RETENTION_DAYS`, expiry enforcement on ingestion, purge endpoint and script, cascade deletion, reset, audit events without content. | There is no automatic scheduler; researchers must run the purge. |
| 7 | **Leaked debug logs** | Logs contain IDs, counts, stages, codes, and durations only. A redaction filter strips content-named fields and truncates long messages. Validation errors do not echo input. Prompt storage is off by default and flagged in the dashboard when enabled. There is no remote logging. | Uvicorn access logs include URL paths (UUIDs only). Tracebacks from unexpected bugs could include local variables if a debugger is attached. |
| 8 | **Malicious file input** | Only `.txt`/`.md` are accepted. Upload names are sanitised (no path separators, `..`, dotfiles, or NUL) and saved under a random prefix with `0600` permissions and `O_EXCL`. Size limits apply (`MAX_UPLOAD_BYTES`, `MAX_PAPER_FILE_BYTES`), UTF-8 decoding is strict, and binary content is rejected. `source_file` paths must resolve inside `PAPERS_DIR` (symlinks resolved). Content is never executed or rendered as HTML (the dashboard uses `textContent`; the CSP has no inline scripts). | Very large pasted text is bounded by request validation (400 kB) but not by a global request-size limit. |
| 9 | **Supply chain / build** | No runtime JS dependencies (only dev tooling), a pinned lockfile, no CDN in the dashboard, and tests that fail on any external URL in source or build output. `scripts/security_check.py` scans staged changes for secrets and data files, and uses gitleaks when installed. | npm dev dependencies are still third-party code at build time. |
| 10 | **Future: mobile and server deployment** | Not implemented. Adapter interfaces only. | These are required before any non-loopback use: authenticated and encrypted transport (TLS with pairing), per-device authorisation, audio never persisted, on-device or local ASR/TTS, rate limiting, encryption at rest, a revised consent flow covering live audio and bystanders, a DPIA/IRB review, and removal of the Swagger CDN dependency. Always-on listening would require a separate ethics review. |
